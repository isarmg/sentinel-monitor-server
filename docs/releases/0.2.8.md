# Sentinel Monitor Server 0.2.8

Sentinel is now the Server side of a multi-brand camera platform. It receives normalized device identity, capabilities, main/sub streams, health, and command results from paired edge Clients, and exposes unified live video and PTZ control without storing vendor camera credentials.

Each instance uses an encrypted renewable authorization code. The administrator can select Server or Client recording storage, remove cancelled unpaired instances, and use the shared list/detail/configuration/log workspace.

Production bootstrap now requires an explicit client-reachable RTSP(S) publish origin and rejects loopback placeholders. Deployment guidance distinguishes loopback control/API ports from the host-bound RTSP, HLS, WebRTC HTTP and WebRTC UDP listeners.

Client snapshots with non-empty camera inventories now use an exact, regression-tested UPSERT mapping. Camera ownership remains immutable across soft deletion, and publishing uses short-lived, camera/profile/action-scoped media tokens instead of placing the long-lived Client API credential in an RTSP URL.
