# 故障排查

先确定故障发生在哪一段：摄像头 → xcoc → RTSPS/MediaMTX → WHEP/HLS → 浏览器。
保留发生时间、实例 ID、操作 ID 与最近一次有效观测时间。

| 症状 | 检查 | 预期结果与下一步 |
|---|---|---|
| 启动失败 | `xcosctl status`、首条启动错误、发行路径与权限 | 使用完整匹配的发行树；按错误修正配置后再启动 |
| 登录失败或循环 | HTTPS、浏览器 Cookie、Origin/Host 和系统时间 | 同源 HTTPS 与安全 Cookie 正常；检查登录限流提示 |
| 实例在线但无画面 | xcoc 本机媒体探测、发布端口、RTSPS 证书、代理路由 | 客户端可发布，浏览器可访问 WHEP/HLS；逐段核对 |
| 观测过期或未知 | MediaMTX 路径清单、网络和协调器日志 | 下一次完整清单保存后恢复 fresh；`/v3/info` 成功仅证明信息接口可读 |
| 录像已配置但无片段 | 录像模式、流就绪、目录权限、磁盘 | 服务端模式下索引与文件持续增长；本地模式去 xcoc 主机查看 |
| 操作长期 pending | 协调器、操作租约、MediaMTX API | 操作得到确定结果或进入未确认状态，再按该状态处理 |
| 操作 unknown | 设备/媒体实际状态及操作记录 | 管理员核实后确认成功、失败或无法确认；确认不会重放原请求 |
| 凭据解密失败 | 当前受保护的 `CREDENTIALS_KEY` | 与已有密文匹配；先找回正确配置，保留原数据 |
| `history_storage_capacity` | 历史预算与磁盘空间 | 系统拒绝新操作，已有结果仍使用预留空间；按容量参考处理 |

## 进一步诊断

按[运维手册](operations.md#doctor-检查)运行 Doctor，区分发行完整性、数据结构、存储、凭据或在线媒体故障。
数据库结构错误时先停止业务写入并保留现场；使用程序身份与精确结构检查定位，不直接改元数据或删锁文件。

日志日期范围、观测有效期、操作人工确认和历史上限见[运行状态参考](runtime-reference.md)。报告问题时附版本、平台、脱敏错误和复现步骤。
